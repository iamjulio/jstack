# Engineer the marketing system

Use this mode for campaign intake/routing, channel adapters, experiment orchestration, claims graders, measurement contracts and outcome telemetry. A single campaign request does not authorize building a new marketing platform.

1. **Establish the failure and baseline.** Trace a real or supplied fixture from intake through asset, publication receipt, event and business record. Identify the boundary losing correctness or useful evidence.
2. **Version the proposed contract.** Define owner, compatibility/migration, canonical records, identity/data scope, exact action grants, caps, idempotency/reconciliation and failure states. Map these to provider capabilities rather than assuming custom fields or transactional guarantees exist.
3. **Implement requested runtime.** If a running factory is requested, build and verify real persistence, claims/leases where supported, channel adapters, receipts, budget accounting, recovery and observability. Instructions and mocked API calls alone prove neither live integration nor enforcement.
4. **Evaluate independently.** Freeze representative fixtures and rubric before comparison. Include success, unsupported claim, stale creative approval, duplicate/timed-out send, active parent with a paused child, incorrect currency units, invalid tracking, delayed conversion, suppression failure, exhausted budget and unavailable integration. Use held-out cases for material harness changes.
5. **Roll out within scope.** Prefer dry-run/replay and narrowly scoped traffic where practical. Verify actual deployed revision, account, caps and receipt-to-outcome linkage. Publish limitations and next owner rather than claiming autonomy from a passing fixture suite.

Track false approvals, invalid claims, duplicate external effects, cost/volume overruns, missing outcome linkage, recovery success, latency and total operating cost. Keep per-case evidence and sample size. A creative score alone cannot establish campaign business value.

An operator reports a grader or attribution defect as separate factory work; it cannot rewrite its own success criteria after viewing performance. A revision to the scoring system needs the appropriate change authority and a fresh baseline comparison. Preserve prior scores and experiment definitions.

For substantive changes, independently forward-test the final instructions in an isolated workspace using a realistic request and minimal raw artifacts. Do not supply the expected conclusion. Limit effects to approved fixtures. Review actual decisions/artifacts, fix observed failures and rerun the affected cases; keep inconclusive review visible.

## Cross-factory dependencies

Persist root/campaign and child ticket IDs, dedupe key, both owners and organization scopes, objective/acceptance, source revision, allowed data, budget reservation, current status and final verification receipt. A request for tracking code does not grant deployment; a software release does not grant campaign activation. Query before resubmitting uncertain requests and reject stale results.

Do not multiply a parent spend grant across child tasks. Stop equivalent cyclic dependencies. Use aggregate or redacted evidence where sufficient, and do not message another chat or person without user authorization. Receiving a request or report does not itself authorize a reply through external messaging tools.
